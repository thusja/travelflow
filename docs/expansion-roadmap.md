# TravelFlow Expansion Roadmap

목적: 현재 코드/문서 상태를 기준으로 앞으로의 확장 개념과 구현 순서를 고정한다.

## 1. 확장 개념

- Platform 안정화: 인증, 캐시, 정책, 에러 규격을 먼저 고정해 기능 추가 시 회귀를 줄인다.
- Domain 확장: 예약/리뷰/쿠폰/플래너 기능을 사용자 가치 중심으로 수직 확장한다.
- 운영 자동화: 관측성, 배치, 데이터 수명주기를 자동화해 운영비를 낮춘다.

## 2. 우선순위 원칙

- 사용자 임팩트가 큰 기능을 먼저 구현한다.
- 데이터 정합성 리스크가 큰 영역(결제성/포인트/쿠폰)을 우선 안정화한다.
- 스키마/정책 변경이 필요한 작업은 배치해 한 번에 검증한다.
- API 계약 변경은 프론트/백엔드 동시 롤아웃이 가능한 단위로 자른다.

## 3. 단계별 추가 순서

### Phase A (지금부터 1~2주): 구조 안정화

- Controller-Service 분리 확장 완료
  - 현재 auth/users/reviews/points에 적용된 패턴을 bookings/planner/suggestions에도 통일
- 공통 에러 처리 래퍼 도입
  - 반복 try/catch를 줄이고 에러 응답 일관성 강화
- API 스펙 최신화
  - 실제 엔드포인트/응답 예시를 docs/api-spec.md와 일치시킴

완료 기준
- 주요 라우트에서 비즈니스 로직이 services로 이동
- 서버 기동 + 핵심 스모크 테스트 통과

### Phase B (2~4주): 도메인 신뢰성 강화

- 예약/쿠폰/포인트 트랜잭션 보강
  - 중복 요청/경합 상황에서 일관된 결과 보장
- 리뷰/예약 제약 강화
  - 완료 예약만 리뷰 가능, soft-delete 조회 규칙 통일
- Storage 전환 1차
  - 프로필/리뷰 이미지를 Supabase Storage 경로 규칙으로 점진 전환

완료 기준
- 예약 생성/취소/쿠폰 등록 시 재시도/멱등성 시나리오 통과
- 로컬 uploads 의존 경로 축소

### Phase C (4~6주): 운영 기능 확장

- BullMQ 스케줄러 재도입
  - 쿠폰 만료 반영, 포인트 만료 처리, 리마인더 작업
- job_runs 관측성 강화
  - 실패율/재시도 횟수/지연 시간 추적
- 캐시 무효화 규칙 고도화
  - 도메인 이벤트 기반 접두사 무효화 표준화

완료 기준
- 배치 작업 실패 시 알림/재시도 정책 검증
- 캐시 hit/miss 및 무효화 지표 확인 가능

### Phase D (6주+): 제품 확장

- 관리자 기능
  - 패키지/쿠폰 운영 화면 및 감사 로그
- 사용자 경험 확장
  - 추천 고도화, 마이페이지 통계, 다국어/접근성 개선
- BFF 경량화
  - 일부 기능 Edge Functions로 점진 분리 검토

완료 기준
- 운영자가 코드 수정 없이 주요 운영 데이터를 관리
- 핵심 사용자 여정 전환율 지표 확인

## 4. 다음 스프린트 실행 항목 (추천)

1. bookings/planner/suggestions를 services 계층으로 분리
2. auth/users/reviews/points 서비스 단위 테스트 추가
3. docs/api-spec.md를 실제 구현 기준으로 동기화
4. uploads -> Supabase Storage 마이그레이션 PoC

## 5. 리스크와 대응

- 리스크: 문서와 코드의 재불일치
- 대응: 기능 머지 시 docs 동시 업데이트를 PR 체크리스트에 포함

- 리스크: 토큰/정책 변경 중 인증 회귀
- 대응: 로그인/리프레시/로그아웃 시나리오를 스모크 테스트로 고정

- 리스크: 배치 도입 시 장애 전파
- 대응: 큐 워커 분리, 최대 재시도/백오프 정책과 실패 알림 선적용
